# Rhythm Read — deployment readiness

This build is configured for a Supabase + Next.js deployment and keeps all server secrets out of browser bundles.

## Before launch

1. Create a fresh Supabase secret API key and a fresh Google OAuth client secret. Any secrets pasted into chat or committed to a repository must be rotated before production.
2. Create `.env.local` from `.env.example` for local development.
3. Run `SUPABASE-ADMIN-ONLY.sql` in the Supabase SQL editor after your main schema.
4. Confirm the `books` Storage bucket is private.
5. Configure Google OAuth redirect URIs for the deployed origin.
6. Run `npm install`, `npm run typecheck`, `npm run build`, then `npm start` locally.
7. Test `/api/health` and confirm `{ "ok": true, "database": "ok" }`.
8. Set the same environment variables in the hosting provider. Never place `SUPABASE_SECRET_KEY`, `AUTH_SECRET`, or `AUTH_GOOGLE_SECRET` in a `NEXT_PUBLIC_*` variable.

- Private Supabase Storage bucket
- Server-side admin authorization
- No browser service-role/secret key
- Signed, short-lived file URLs
- Security response headers
- No demo catalog fallback
- Published-only public catalog
